# Shopping Backend

쇼핑몰 Frontend의 주문 흐름을 실제로 연결하기 위해 구성한 NestJS API 서버입니다.

회원과 비회원 주문부터 입금 확인, 배송, 취소·반품까지
쇼핑몰에서 필요한 기본적인 주문 상태 흐름을 다룹니다.

외부 PG와 택배사 API는 프로젝트 범위에서 제외하고,
무통장 입금과 관리자 배송 처리를 기준으로 구현했습니다.

## 주요 구현

- 회원가입 / 로그인 및 사용자 정보 조회
- 상품 / 카테고리 조회
- 회원 / 비회원 주문
- 주문 조회 및 취소·반품 요청
- 관리자 입금 확인 및 배송 처리
- 관리자 반품 승인 / 거절
- 주문 처리에 따른 재고 상태 반영
- 공지 / QnA / FAQ 조회 및 관리

## 주문 흐름

```text
상품 선택
→ 주문 생성
→ 입금 대기
→ 관리자 입금 확인
→ 배송 처리
→ 배송 완료
→ 취소 / 반품
```

주문 생성에서 끝내지 않고,
사용자가 주문 이후의 상태를 계속 확인할 수 있도록
Frontend와 Backend의 흐름을 연결하는 데 중점을 두었습니다.

비회원도 주문 이후 흐름을 확인할 수 있도록
주문번호와 주문 시 입력한 정보를 이용해
주문 조회, 취소 요청과 반품 요청을 할 수 있도록 구성했습니다.

## 프로젝트에서 정리한 부분

처음에는 기능 구현부터 진행하면서
Frontend와 Backend의 요청·응답 형식이나 주문 상태 기준을 여러 번 수정해야 했습니다.

이후에는 주문 상태와 예외 조건,
기능별 요청·응답 구조를 먼저 정리한 뒤 구현하는 방식으로 바꿨습니다.

이 경험은 이후 프로젝트에서
기능 구현 전에 서비스 정책과 API 기준을 먼저 확인하게 된 계기가 되었습니다.

## Tech Stack

`NestJS` `TypeScript` `PostgreSQL` `Prisma`  
`JWT` `REST API`

## Run

```bash
npm install
npm run start:dev
```

필요한 환경변수는 프로젝트의 환경 설정에 맞게 구성해야 합니다.
